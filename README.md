# BEQ HAIR CLINIC Toolkit — ระบบจัดการภาพคนไข้และติดตามผล

เว็บแอป Next.js สำหรับให้ BT ถ่าย/อัปโหลดรูปและวิดีโอคนไข้ปลูกผม, แพทย์/ผู้ตรวจดูและเปรียบเทียบตามระยะ, เซลล์กรอกข้อมูล และผู้บริหารดูรายงาน
ข้อมูลตารางเก็บใน **Google Sheets** รูป/วิดีโอเก็บใน **Google Drive** — credentials และ refresh token อยู่ฝั่ง server เท่านั้น เบราว์เซอร์อัปโหลดตรงด้วย resumable URL ที่ server ออกให้หลังตรวจสิทธิ์

## สิทธิ์ตามบทบาท

| บทบาท | กรอก/ส่งฟอร์ม | อัปโหลดรูป/วิดีโอ | ดูรูป/วิดีโอ + ค้นหาคนไข้ | ดูรายงาน | จัดการระบบ |
|---|:-:|:-:|:-:|:-:|:-:|
| ผู้ดูแลระบบ (admin) | ✓ | ✓ | ✓ | ✓ | ✓ |
| แพทย์ (doctor) | | | ✓ | ✓ | |
| BT (กรอก D0/F/U และดู Day 0 ของ HN เดียวแบบอ่านอย่างเดียว) | ✓ | ✓ | | | |
| เซลล์ (sales) (กรอก D0/F/U และดู F/U ในความดูแลแบบอ่านอย่างเดียว) | ✓ | | | | |
| หัวหน้าเซลล์ (sales_lead) (เห็นเฉพาะฟอร์ม Day 0) | ✓ | | | ✓ | |
| ผู้ตรวจ (checker) | | | ✓ | | |
| HR (hr) | | | ✓ (ค้นหา ดูรูป และดาวน์โหลดไฟล์) | | |

แก้ตารางได้ที่ `lib/roles.js` (ฝั่ง server ตรวจสิทธิ์ทุก API)
BT และเซลล์มีสิทธิ์กรอกทั้งฟอร์ม Day 0 และ F/U แต่สิทธิ์ดูข้อมูลย้อนหลังไม่ได้ขยาย: BT เปิดดู Day 0 ได้เฉพาะ HN ที่กำลังกรอก F/U และไม่สามารถเปิดรูป Day 0 ได้ ส่วนเซลล์ดู F/U ของคนไข้ที่ผูกกับเซลล์ในฟอร์มล่าสุดที่มีช่องเซลล์ โดยไม่สามารถแก้ไขหรือดูสื่อได้ ฟอร์มใหม่ผูกกับ `cellId` ซึ่งเป็นรหัสผู้ใช้ที่ไม่เปลี่ยนเมื่อแก้ชื่อที่แสดงผล; ข้อมูลเก่าที่ยังไม่มี `cellId` จะ resolve จากชื่อเซลล์เฉพาะเมื่อพบบัญชีที่เปิดใช้งานเพียงบัญชีเดียว หากชื่อซ้ำหรือห่างจากรายการจะไม่เปิดสิทธิ์อัตโนมัติ

## นำเข้า / ส่งออกข้อมูลเคส (CSV / Excel)

เมนู **นำเข้า/ส่งออกข้อมูล** (`/data`) — นำเข้าได้ทั้ง `.xlsx` (ชีตแรก, เซลล์วันที่ของ Excel อ่านเป็นวันที่จริง, ใหญ่สุด 3 MB) และ `.csv` — เฉพาะข้อมูลเคสในรูปตาราง ไม่รวมรูปและวิดีโอ

- **ส่งออก** (`exportData`: ผู้ดูแลระบบ, หัวหน้าแพทย์) เป็น `.xlsx` หรือ `.csv` กรองตามชนิดฟอร์มและช่วง “เวลาที่ส่ง” ได้ ทุกครั้งบันทึกใน Audit log
- **นำเข้า** (`importData`: ผู้ดูแลระบบ) จาก `.xlsx` หรือ `.csv` — ตรวจสอบให้ดูก่อน (ยังไม่บันทึก) แล้วค่อยยืนยัน แถวที่ผิดพลาด/ซ้ำถูกข้าม ไม่ทับข้อมูลเดิม
- คอลัมน์ 1–18: เวลาที่ส่ง · เลข OPD · ชื่อคนไข้ · ปลูกผมย้ายราก · บริเวณที่ทำ · ปลูกด้วย Stem cell · งานฉีดและอื่นๆ · วันที่ปลูก · ประเภทเคส · เซลล์ · แพทย์ · ผู้ถ่าย · ตรวจสอบโดย · ผู้ส่ง · จำนวนไฟล์ · สถานะ · ที่มา · โฟลเดอร์ภาพ (จำนวนไฟล์ สถานะ โฟลเดอร์ภาพ ส่งออกอย่างเดียว) — ไฟล์เก่าที่รวม Stem cell กับงานฉีดไว้ช่องเดียวยังนำเข้าได้ ตามด้วย “ข้อมูลเพิ่มเติม” ไม่บังคับ (เพศ อายุ สัญชาติ ครั้งที่ ฯลฯ)
- เลือก **ชนิดไฟล์** ก่อนนำเข้า: **Day 0** หรือ **F/U** (ทุกแถวเป็นชนิดนั้น มีเทมเพลตแยก — F/U ต้องมีคอลัมน์ “วันที่เข้ามารับบริการ (F/U)”) หรือ **ปนกัน** (ช่อง “ที่มา” ที่มีคำว่า F/U = ติดตามผล นอกนั้นเป็น Day 0) · ถ้า “ที่มา” ของแถวขัดกับชนิดที่เลือก แถวนั้นจะถูกปฏิเสธ
- ที่ต้องมีตอนนำเข้า: เลข OPD, ชื่อคนไข้, วันที่ปลูก
- วันที่แนะนำ `2026-11-27` · ถ้าใช้ `/` ระบบดูทั้งไฟล์ว่าเป็น วัน/เดือน/ปี หรือ เดือน/วัน/ปี (ไฟล์ที่ปนสองแบบถูกปฏิเสธ ถ้าทุกค่ากำกวม เช่น 3/4/2026 อ่านเป็น วัน/เดือน และขึ้นคำเตือน) · ไฟล์ใหญ่สุด 4 MB
- ตัวเลือกต่าง ๆ (วิธีปลูก บริเวณ ปลูกด้วย ประเภทเคส) ต้องอยู่ในรายการที่ตั้งไว้ใน Settings · ชื่อต้องตรงกับข้อมูลเดิมของ HN เดียวกัน · สูงสุด 2,000 แถวต่อครั้ง
- ไฟล์ CSV ที่เซฟจาก Excel ภาษาไทยแบบ “CSV (Comma delimited)” (รหัส Windows-874) ระบบถอดรหัสให้อัตโนมัติ

## ลองในเครื่องโดยยังไม่ต้องมี Google (โหมดทดลอง)

```bash
npm install
DATA_MODE=mock npm run dev      # เปิด http://localhost:3000
```
มีบัญชีทดลอง `admin / doctor / bt / sales / lead / checker / hr` รหัสผ่าน `demo1234` และข้อมูลสมมติ ข้อมูลเก็บในโฟลเดอร์ `.data` (ใช้ใน production ไม่ได้) รัน `npm test` เพื่อทดสอบ resumable upload ไฟล์ใหญ่, media lock, การแยกสิทธิ์เซลล์ และ request id/hash

## ตั้งค่า Google (ทำครั้งเดียว)

ระบบใช้ OAuth ของ **บัญชี Google เดียว** (บัญชีบริษัท Workspace ที่เป็นเจ้าของข้อมูล) ไม่ใช้ service account เพราะ service account ไม่มีพื้นที่เก็บไฟล์ใน My Drive

1. ไปที่ [Google Cloud Console](https://console.cloud.google.com) → สร้างโปรเจกต์ (ถ้าใช้ Workspace ให้สร้างในองค์กร)
2. **APIs & Services → Library** เปิด **Google Sheets API** และ **Google Drive API**
3. **OAuth consent screen** → ถ้าเป็น Workspace เลือก **Internal** (refresh token ไม่หมดอายุ) / ถ้าเป็น Gmail ส่วนตัวเลือก External แล้วกด **Publish app** (ถ้าค้างสถานะ Testing token จะหมดอายุใน 7 วัน)
4. **Credentials → Create Credentials → OAuth client ID → Desktop app** แล้วคัดลอก Client ID/Secret
5. คัดลอก `.env.example` เป็น `.env.local` ใส่ `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`, `SESSION_SECRET` (`openssl rand -base64 48`) และ `ADMIN_PASSWORD`
6. `npm run get-token` → เปิดลิงก์ที่แสดง ล็อกอินด้วยบัญชีเก็บข้อมูล → นำ `GOOGLE_REFRESH_TOKEN=...` ที่ได้ใส่ใน `.env.local`
   (สิทธิ์ที่ขอ: Sheets + Drive แบบ `drive.file` คือเห็นเฉพาะไฟล์ที่แอปนี้สร้างเอง)
7. `npm run setup` → สร้าง Google Sheet (ถ้า `SHEET_ID` ว่าง) พร้อมแท็บ Users, Records, Media, Options, Folders, Audit และสร้างผู้ดูแลระบบคนแรก — นำ `SHEET_ID=...` ที่แสดงใส่ `.env.local` ถ้ามี Sheet จากเวอร์ชันเดิมให้รันคำสั่งนี้ซ้ำเพื่อเพิ่มคอลัมน์ `reservedAt` ในแท็บ Media และ `cellId`, `requestId`, `requestHash`, `requestBy` ท้ายแท็บ Records (แก้แถวหัวคอลัมน์เท่านั้น ไม่เลื่อนหรือลบข้อมูลเดิม)
8. `npm run build && npm start` แล้วล็อกอินด้วย admin → เพิ่มผู้ใช้ที่เมนู **จัดการผู้ใช้**, เพิ่มรายชื่อแพทย์/เซลล์/ทีมงานที่เมนู **จัดการฟอร์ม**

> ห้ามเปิด Sheet หรือโฟลเดอร์ Drive เป็นสาธารณะ — รูปทุกไฟล์ถูกส่งผ่านเว็บหลังตรวจสิทธิ์เท่านั้น
> เมื่อย้ายจากบัญชีทดสอบเป็นบัญชี Workspace ของบริษัท: ทำข้อ 1–7 ใหม่ด้วยบัญชีบริษัท (Sheet/โฟลเดอร์ใหม่) และย้ายไฟล์เดิมด้วยมือถ้าต้องการ

## Deploy

ต้องตั้ง Environment Variables ตาม `.env.example` ทุกตัวที่ที่ deploy (ไม่ต้องตั้ง `DATA_MODE`)

- **Vercel (ฟรีสำหรับทดลอง):** import repo → ใส่ env → Deploy (`vercel.json` ตั้ง region สิงคโปร์ให้แล้ว เพื่อให้ใกล้ไทย)
  ⚠️ แผน Hobby ของ Vercel อนุญาตเฉพาะการใช้งานส่วนบุคคล/ไม่เชิงพาณิชย์ — เมื่อใช้งานจริงในบริษัทต้องใช้แผนที่เสียเงิน หรือย้ายไป VPS
- **VPS/เซิร์ฟเวอร์บริษัท:** `docker build -t beq-toolkit . && docker run -p 3000:3000 --env-file .env.local beq-toolkit` (หรือ `npm run build && npm start`) ด้านหน้าใส่ HTTPS (Caddy/Nginx) — ไม่ติดเพดานขนาดคำขอ/เวลาของ serverless

## ความเร็วและความเสถียร

- อ่านชีตครั้งเดียวต่อรอบ (batchGet) แล้ว cache ในหน่วยความจำ 20 วินาที เขียนแล้วอัปเดต cache ทันที
- บราว์เซอร์อัปโหลดรูปได้ 4 ไฟล์พร้อมกัน และวิดีโอทีละไฟล์ ส่งตรงเข้า Drive แบบ resumable ชิ้นส่วน 4 MiB ต่อครั้ง ถ้าสัญญาณหลุดจะตรวจสอบ offset และส่งต่อจากส่วนที่เซิร์ฟเวอร์รับได้โดยไม่ส่งจากศูนย์
- ไฟล์ที่มี resumable session หมดอายุจะเริ่ม session ใหม่ด้วย media ID เดิม ข้อมูลที่ส่งค้างจะถูกตรวจสอบก่อนส่งต่อ และระบบลองอัปโหลดใหม่เมื่อออนไลน์
- บันทึกสถานะไฟล์ลง Sheets แบบ rolling batch ครั้งละ 10 รายการ และยืนยันซ้ำได้ด้วย media ID ถ้าคำตอบหลังบันทึกหาย
- การสร้างฟอร์มส่ง `requestId` ที่คงเดิมระหว่างการลองใหม่ พร้อม hash ของข้อมูลฝั่ง server คำขอเดิมที่มีข้อมูลตรงกันจะคืนฟอร์มเดิม ส่วนข้อมูลต่างกันจะปฏิเสธไม่ผูกไฟล์เข้ากับฟอร์มอื่น
- รูปและวิดีโอส่งเป็นไฟล์ต้นฉบับ ไม่ย่อ ไม่บีบอัด JPEG และไม่ encode วิดีโอใหม่
- หน้าดูรูปใช้รูปย่อ โหลดเฉพาะกลุ่มที่เปิดอยู่ (เปิด/ปิดแต่ละระยะและแต่ละกลุ่มได้) และ browser cache รูป 1 วัน

## ร่างอัตโนมัติ พรีวิว และหน้าฟอร์ม

- ฟอร์มทุกเฟส กลุ่มรูป มุมถ่าย ช่องรูป ภาพเพิ่มเติม และวิดีโอพับ/กางได้
- ค่าฟอร์มและไฟล์ที่เลือกเก็บใน IndexedDB ของเบราว์เซอร์อัตโนมัติ รีเฟรชหรือปิดหน้าโดยไม่ตั้งใจแล้วกลับมาคืนค่าและไฟล์เดิมได้ การเก็บ metadata และ blob ใช้ transaction เดียวกัน
- ถ้า blob ของไฟล์ที่ยังไม่ส่งหาย ระบบจะแสดงสถานะ “missing” และเลือกไฟล์เดิมใหม่ได้เมื่อชื่อ ชนิด และขนาดตรงกัน จะไม่บันทึกฟอร์มจนกว่าจะแนบไฟล์ครบ ส่วนไฟล์ที่ sent แล้วสามารถ finalize ด้วย media ID ได้
- ถ้าสร้างฟอร์มแล้วไฟล์ค้าง ระบบจะล็อกข้อมูลและเข้าสู่โหมดลองอัปโหลดต่อ แทนการสร้างฟอร์มซ้ำ
- กดรูปหรือวิดีโอก่อนส่งเพื่อเปิดพรีวิวเต็มจอ รูปซูมได้ 100–500% ด้วยปุ่ม เมาส์ คีย์บอร์ด และการแตะสองนิ้ว วิดีโอใช้เครื่องเล่นของเบราว์เซอร์และมีปุ่มเต็มจอ
- ถ้าเบราว์เซอร์เล่นไฟล์ชนิดนั้นไม่ได้ จะมีปุ่มดาวน์โหลดเพื่อเปิดด้วยแอปในเครื่อง

## ข้อจำกัดที่ควรรู้

- **Google Sheets ไม่ใช่ฐานข้อมูล**: โควตาประมาณ 60 คำขอ/นาที/บัญชี เหมาะกับผู้ใช้หลักสิบคนพร้อมกัน เมื่อคนไข้เกินหลักหมื่นแถวหรือผู้ใช้เพิ่มมาก แนะนำย้ายไป PostgreSQL (เช่น Neon/Supabase) — โค้ดแยกชั้นข้อมูลไว้ที่ `lib/db.js` แล้ว
- เวอร์ชันนี้รันได้ครบในโหมดทดลอง แต่ **ส่วนเชื่อม Google จริง (Sheets/Drive/อัปโหลดตรงเข้า Drive/เล่นวิดีโอผ่านเว็บ) ยังไม่ได้ทดสอบกับบัญชี Google จริง** ทดสอบกับตัวจำลอง API เท่านั้น — ควรลองอัปโหลดรูปและวิดีโอขนาดจริงหลังตั้งค่าเสร็จ ถ้าเล่นวิดีโอผ่านเว็บติดขัดบน Vercel ให้เปิดผ่านลิงก์ “เปิดใน Drive” หรือ deploy บน VPS
- อัปโหลด resumable รองรับไฟล์ถึง `MAX_VIDEO_MB` และลองซ้ำอัตโนมัติในแต่ละ session แต่ถ้าไฟล์ใหญ่มากจนเกิน timeout ของ Vercel แนะนำ deploy บน VPS
- ร่างใน IndexedDB ไม่ได้เข้ารหัสและผูกกับเบราว์เซอร์/โปรไฟล์เครื่องนั้น การล้างข้อมูลเว็บไซต์จะลบร่าง กรุณาใช้เครื่องส่วนตัวและอย่าเปิดร่างคนไข้บนเครื่องสาธารณะ
- การจองไฟล์กันชนกันในระบบปัจจุบันทำในโปรเซส server เดียว ถ้า deploy หลาย instance พร้อมกันต้องเพิ่ม distributed lock และตรวจไฟล์ค้างใน Drive เป็นประจำ
- ถ้าสัญญาณหลุดหลังจาก Drive สร้าง resumable session แต่ก่อนเขียนแถวจองใน Sheets อาจมีไฟล์ค้างที่ระบบไม่รู้จักได้
- **PDPA:** รูปคนไข้เป็นข้อมูลอ่อนไหว ระบบบันทึก audit (ใคร/เมื่อไร/ทำอะไร) ไว้ที่ Settings แต่ฟอร์มขอความยินยอม นโยบายเก็บรักษา และสัญญากับผู้ให้บริการ ต้องให้ฝ่ายกฎหมายของบริษัทกำหนด
